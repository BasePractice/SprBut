# Приведение кода к qulice

Профиль `qulice` включается на JDK 21+ и работает на фазе `verify`.
Проверка одного модуля:

```bash
mvn -pl 05-annotations-basics -DskipTests package com.qulice:qulice-maven-plugin:0.35.0:check
```

Конвенции, которых требует qulice сверх RULE.md, и то, что и почему
погашено точечно, описаны в [RULE.md](RULE.md), раздел «Qulice».

Помимо Checkstyle и PMD qulice запускает ErrorProne и проверку зависимостей.
Проверка зависимостей отключена в модулях, которые подключают стартеры
Spring Boot: смысл стартера в том и состоит, что он приносит согласованный
набор зависимостей, а код пользуется ими напрямую. В модуле 10 по той же
причине отключён ErrorProne — он компилирует исходники без процессоров
Lombok и MapStruct и потому не видит того, что они дописывают.

## Порядок разбора

Модули берутся от самых чистых к самым запущенным. Каждый доводится
до нуля отдельным коммитом, после чего строка таблицы обновляется.

Очередь: ~~05~~ → ~~06~~ → ~~10~~ → ~~01~~ → ~~23~~ → ~~16~~ → ~~08~~ → ~~14~~ → ~~18~~ →
~~19~~ → ~~03~~ → ~~09~~ → ~~20~~ → ~~11~~ → ~~13~~ → ~~12~~ → ~~17~~ → ~~15~~ → ~~02~~ → ~~04~~ → ~~07~~.

Все модули приведены к нулю. `mvn clean install` проходит с профилем
`qulice` и всеми тестами.

Модули 20–23 написаны сразу по правилам: столбец «было» для них пуст.
В 23-spring-cloud дополнительно отключён поиск дубликатов — одиннадцать
jar-ов resilience4j несут одинаковый `COPYRIGHT.txt`, и это считается
конфликтом ресурсов.
