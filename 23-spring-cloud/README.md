## Что в презентации

> Конфигурация вынесена из приложения: Config Server. Service discovery:
> сосед находится по имени, не по адресу. Балансировка на стороне клиента:
> Spring Cloud LoadBalancer. Декларативный HTTP-клиент: интерфейс вместо кода
> запроса. Resilience4j: circuit breaker, retry, ограничение нагрузки.
> Spring Cloud Gateway — единая точка входа в систему сервисов. Micrometer
> Tracing: один идентификатор на всю цепочку. Отказ соседа — не авария,
> а нормальный режим работы.

Модуль начинается с допущения, которого не было в остальном курсе: рядом
есть другие приложения, они отвечают по сети, и любое может не ответить.

Реестр здесь простой — `SimpleDiscoveryClient`, читающий адреса из настроек.
Eureka и Consul отличаются тем, откуда берётся список и как быстро он
обновляется, но не тем, как им пользуются.

## Расширенный пример

[`Breaker`](src/main/java/ru/sprbut/m23/extended/Breaker.java) — предохранитель,
пойманный за работой.

Сосед падает на каждом вызове, запросов делается двадцать — а до сети доходит
лишь несколько первых. Разница между числом запросов и числом попыток и есть
та защита, ради которой всё затевалось: поток, ждущий ответа от мёртвого
сервиса, занят и не обслуживает никого.

Каждый опыт берёт свой предохранитель. Тот, что уже разомкнулся в прошлый раз,
ответил бы отказом, не сделав ни одной попытки, и показал бы не работу защиты,
а её последствия.

## Ключевые выводы

* Между сервисами появляется третий исход вызова — «не отвечает». В монолите
  метод либо выполняется, либо бросает исключение; здесь молчание соседа
  не редкость, а нормальный режим.
* Имя сервиса вместо адреса — не удобство, а условие того, что переезд соседа
  или добавление копий не требует правки кода и перезапуска.
* Балансировщик живёт в вызывающем, а не отдельной машиной посередине.
  Отсюда и название «клиентская балансировка».
* Реализацию декларативного клиента собирает динамический прокси — то самое
  средство из [модуля 04](../04-reflection-advanced/README.md), только здесь
  оно делает настоящую работу. С приходом HTTP Interface в сам Spring
  отдельная библиотека для той же идеи перестала быть нужна.
* Запасной ответ — решение предметной области, а не техники. «Ноль на складе»
  безопаснее выдуманного числа, но опаснее честной ошибки, если от этого числа
  зависит списание денег.
